## 3. SecOps SOAR 4-Stage Cloud Identity Eviction & Proxy Isolation Playbook

CISA AA26-237A demonstrated that evicting an attacker from on-premises Active Directory fails if the attacker has stolen Primary Refresh Tokens (PRTs) or injected OAuth Client Secrets into cloud applications. Execute this 4-stage SecOps SOAR playbook upon confirmed hybrid identity compromise (note: when operating as an interactive AI agent during alert triage outside a pre-authorized SOAR playbook, always obtain explicit human analyst confirmation before executing disruptive containment actions in Stages 1, 3, or 4):

1. **Stage 1: Session & PRT Revocation (Human Confirmation Required in Interactive Triage)**:
   - After confirming user/session scope with the analyst (or via pre-authorized SOAR playbook trigger), execute Microsoft Graph API `POST /users/{id}/revokeSignInSessions` and `invalidateAllRefreshTokens` to invalidate stolen PRTs and continuous access evaluation (CAE) sessions.
   - For Google Cloud / Workspace, invoke Admin SDK `users.signOut` and revoke OAuth 2.0 token grants.
2. **Stage 2: Automated Audit of Trailing 7-Day Workload Identity Mutations**:
   - Query `AZURE_AD`, `GCP_CLOUDAUDIT`, and `AWS_CLOUDTRAIL` for any `Add service principal credentials`, `CreateServiceAccountKey`, or `CreateAccessKey` actions performed by the compromised identity over the last 7 days.
3. **Stage 3: OMB M-25-21 Human-in-the-Loop (HITL) Gate for Production Secret Purge**:
   - Surface newly created `keyId` / `customKeyIdentifier` artifacts in the SecOps SOAR case war room.
   - Require explicit SOC Duty Officer approval (satisfying **OMB M-25-21 high-impact AI/automation governance**) before executing `removePassword` / `removeKey` (Entra ID) or `projects.serviceAccounts.keys.delete` (GCP) on production service principals.
4. **Stage 4: Internal SOCKS Proxy Pivot Host Identification & Quarantine (`T1090.001`)**:
   - Because attackers proxy cloud API calls through compromised internal workstations via SOCKS to satisfy Conditional Access IP checks, correlate the cloud API request timestamp (`event_timestamp`) against internal firewall / Zeek / EDR (`NETWORK_CONNECTION`) logs destined to `login.microsoftonline.com` or `oauth2.googleapis.com`.
   - Require explicit analyst confirmation during interactive triage (or execute via pre-authorized SOAR containment block) before isolating the internal workstation originating the proxy tunnel via EDR.

## 4. Entity Graph Tier-0 / HVA Zero-Drop Guardrail

To prevent Organization A's failure mode (where SOC analysts closed an SCCM lateral movement alert as a false positive after failing to identify the system owner in chat):

- Ingest **Snipe-IT CMDB** and **CISA CDM HWAM/SWAM** feeds into Google SecOps `ENTITY_CONTEXT`.
- Tag all Endpoint Configuration Managers (SCCM, Enterprise Mobility Management [MDM / EMM_AUDIT], Jamf, Ansible, and Kubernetes cluster controllers), Domain Controllers, Entra Connect Sync servers, and OT Bastion Jump Hosts with `asset.tier = "TIER_0_HVA"` and populate `asset.owner_handle`.
- **SOAR Closure Lock**: Block Tier-1 analysts from closing any alert involving a `TIER_0_HVA` asset as "False Positive" or "Benign" without automated secondary approval from the designated Asset Owner.
