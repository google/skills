## Requirements

- Android Gradle plugin 8.10 or newer (AI packs need 8.8, device targeting
  8.10).
- Kotlin {{KOTLIN_MIN}} or newer (the Kotlin Gradle plugin): older Kotlin
  compilers cannot read LiteRT {{LITERT_MAVEN_RELEASE}}'s Kotlin API.
- `minSdk` 31 or higher.
- arm64-v8a only (`abiFilters`, step 6): bundletool requires the same ABIs in
  every module that has native libraries, and the Google Tensor runtime has
  only arm64-v8a. Devices that do not support arm64-v8a can then no longer
  install the app.
- The Google Tensor NPU itself is used only on Android 16 (API 36) or newer
  with NPU support; other devices and builds get the CPU model.
- Nothing else to download: the NPU runtime comes from Google Maven.

## Steps

1. **Copy the modules** into your project root, keeping the paths:
   `ai_packs/{{PACK_NAME}}/` and `litert_npu_runtime_libraries/` (two modules:
   `google_tensor_runtime` and `runtime_strings`). If your project already
   has LiteRT's `litert_npu_runtime_libraries/runtime_strings`, keep yours.
2. **Device targeting:** copy `ai_packs/device_targeting_configuration.xml` to
   `{{APP_MODULE_DIR}}/device_targeting_configuration.xml`. If the app already
   has one, add these `<config:device-group>` elements to it, unchanged: the
   same names are used by the AI pack folders and by the
   `google_tensor_runtime` module.
3. **CPU model:** copy `cpu_gpu/{{MODEL_NAME}}_cpu_gpu.tflite` to
   `{{APP_MODULE_DIR}}/src/main/assets/litert/`.
4. **Loader:** copy `kotlin/TensorModelLoader.kt` into your sources and set
   its `package` line (now `{{KOTLIN_PACKAGE}}`) to where you put it.
5. **`settings.gradle.kts`:**

   ```kotlin
   include(":ai_packs:{{PACK_NAME}}")
   include(":litert_npu_runtime_libraries:runtime_strings")
   include(":litert_npu_runtime_libraries:google_tensor_runtime")
   ```

6. **`{{APP_MODULE_DIR}}/build.gradle.kts`:**

   ```kotlin
   android {
     defaultConfig {
       minSdk = 31 // or higher
       ndk { abiFilters.add("arm64-v8a") }
     }
     // LiteRT finds the NPU runtime by listing the app's native library
     // directory, so native libraries must be extracted at install time.
     packaging { jniLibs { useLegacyPackaging = true } }

     assetPacks.add(":ai_packs:{{PACK_NAME}}")
     dynamicFeatures.add(":litert_npu_runtime_libraries:google_tensor_runtime")

     bundle {
       deviceTargetingConfig = file("device_targeting_configuration.xml")
       deviceGroup {
         enableSplit = true
         defaultGroup = "other"
       }
     }
   }

   dependencies {
     implementation("com.google.ai.edge.litert:litert:{{LITERT_MAVEN_RELEASE}}")
     implementation(project(":litert_npu_runtime_libraries:runtime_strings"))
   }
   ```

   Groovy DSL: the same blocks with `assetPacks = [":ai_packs:{{PACK_NAME}}"]`,
   `dynamicFeatures = [":litert_npu_runtime_libraries:google_tensor_runtime"]`
   and `deviceTargetingConfig = file('device_targeting_configuration.xml')`.
   The `google_tensor_runtime` module depends on `project(":{{APP_MODULE}}")`;
   change that line if your app module has another name.

7. **`gradle.properties`:** `android.experimental.enableDeviceTargetingConfigApi=true`
8. **Manifest:** {{PERMISSIONS_STEP}}
9. **Use the model:**

   ```kotlin
   // In a coroutine, off the main thread:
   val loaded = TensorModelLoader.load(context) // keep it while you need it
   val inputs = loaded.model.createInputBuffers()
   val outputs = loaded.model.createOutputBuffers()
   inputs[0].writeFloat(myInput)
   loaded.model.run(inputs, outputs)
   val result = outputs[0].readFloat()
   ```

   `model_io.json` lists the model's input and output names, shapes and
   types. Close the buffers, then `loaded.close()`, when you are done.

## Test on a Pixel before releasing

```bash
./gradlew :{{APP_MODULE}}:bundleRelease   # or bundleDebug
java -jar bundletool-all.jar build-apks --local-testing --overwrite \
  --bundle={{APP_MODULE_DIR}}/build/outputs/bundle/release/{{APP_MODULE_LAST}}-release.aab \
  --output=/tmp/app.apks
java -jar bundletool-all.jar install-apks --apks=/tmp/app.apks \
  --device-groups={{FIRST_GROUP}}
adb shell pm path <your.application.id>   # expect a google_tensor_runtime split
adb logcat -s LiteRtTensor                # after the app loads the model
```

- `--device-groups` is the phone's group: `adb shell getprop ro.soc.model`
  prints `Tensor G5` for `Google_Tensor_G5`, `Tensor G6` for
  `Google_Tensor_G6`.
- `./gradlew installDebug` installs only the base APK, without the AI pack
  and the `google_tensor_runtime` module, so the loader falls back to the CPU
  model. Test with the bundletool commands above: they install what Google
  Play would deliver to the phone.
- Use `bundletool-all-<version>.jar` 1.18.0 or newer from
  https://github.com/google/bundletool/releases: it includes aapt2. Other
  bundletool builds need `--aapt2=<Android SDK>/build-tools/<version>/aapt2`
  on `build-apks`.
- The log line reads `LITERT_TENSOR_RESULT {"path":"npu", ...}` when the model
  runs on the TPU. `"path":"cpu"` comes with an `npu_error` saying why.
- Local testing cannot update an installed app: uninstall it first.
  `fast-follow` packs behave like `on-demand` packs in local testing.

## If something fails

| Symptom | Fix |
|---|---|
| bundletool: `Module '...' refers to device groups [...] which are not in the list [...]` | The app's `device_targeting_configuration.xml` is missing a group: copy it from this package (step 2). |
| Gradle: `Plugin with id 'com.android.ai-pack' not found` | The Android Gradle plugin is older than 8.8, or not declared in the root build file. |
| Kotlin: `class 'com.google.ai.edge.litert...' was compiled with an incompatible version of Kotlin` | Use Kotlin {{KOTLIN_MIN}} or newer for the app. |
| `"path":"cpu"` with `npu_error` about the device | Expected on other phones and on Android builds without NPU support. |
| `"path":"cpu"` on a packaged Pixel | Check `adb shell pm path` for the `google_tensor_runtime` split, `useLegacyPackaging = true`, and that `litert` and `litert-npu-runtime-google-tensor` have the same version. |
